# Dashboard — 대시보드 기획

로그인 성공 후 진입하는 랜딩 화면. auth vertical slice에서 **인증 이후의 유일한
화면**이며, 현재 범위는 "**활성 세션 관리**"에 집중한다(내 계정이 지금 어디에서
로그인돼 있는지 보고, 원격으로 끊는다). 개인정보 미저장 원칙([auth.md](./auth.md))은
여기서도 그대로 유지된다 — 대시보드는 세션 메타(발급/만료 시각)만 다루고 PII는 담지 않는다.

> **다음 수직 슬라이스는 WebRTC.** 사이드바에 `WebRTC` 항목을 미리 예약해 두었고,
> 해당 슬라이스를 시작할 때 화면을 붙인다. 지금은 비활성(내비게이션 자리만).

## 1. 기능 요약 (Feature Log)

### 세션 연결 상태 — 구현 (server · web · iOS · Android)

- 추가: 2026-08-23

#### 결정됨: 소켓은 **신호만** 나르고 목록은 HTTP로 다시 가져온다

소켓이 `SessionListItem[]`을 통째로 푸시하면 편할 것 같지만, 그러면 클라이언트가 세션
목록을 얻는 경로가 둘이 된다. 그런데 스탬핑 · 공유 회전 · stale 응답 거부 · 중앙화된
"세션 종료" 공지는 **HTTP 경로에만** 붙어 있다([auth.md §6.3](./auth.md)). 소켓이 목록을
직접 주입하면 그 넷을 전부 우회하고, 특히 **세션 N이 연 소켓이 세션 N+1의 화면에 목록을
밀어 넣는** 경로가 열린다.

→ 서버는 `sessionsChanged`(페이로드 없음)만 보내고, 클라이언트가 기존
`GET /auth/sessions`를 다시 부른다. 재조회가 이미 올바른 경로를 타므로 네 경계가 설계만으로
지켜지고, 신호가 멱등해 순서 문제도 없다.

- **재조회는 목록을 비우지 않는다**(`refresh()`) — 다른 기기가 하나 붙었다고 카드가
  "불러오는 중"으로 접혔다 펴지면 목록 전체가 깜빡인다(§4의 같은 규칙).
- **자동 폴링이 아니다.** 화면에 떠 있는 내내 서버를 두드리는 것이 아니라, 실제로 바뀐
  순간에만 한 번 가져온다 — §4의 "자동 폴링은 두지 않는다"와 충돌하지 않는다.

#### 결정됨: 정렬 키는 **움직이지 않는 값**이어야 한다

저장소가 주는 기본 순서는 사용자별 인덱스의 score, 즉 **만료 시각**이다. 그런데 그 값은
회전할 때마다 다시 쓰인다 — 그리고 **지금 쓰고 있는 세션이 가장 자주 회전한다.** 그래서
목록을 보고 있는 동안 현재 세션 행이 주기적으로 맨 아래로 떨어졌다(액세스 토큰이 짧을수록
더 자주). 새로 만든 세션도 만료가 가장 늦어 맨 아래에 붙었다.

→ **현재 세션을 맨 위에 고정하고, 나머지는 `startedAt` 최신순.** 동점이면 세션 id로 가른다
(빠르게 두 번 로그인하면 시작 시각이 같을 수 있다).

- **`startedAt`은 세션이 사는 동안 바뀌지 않는다.** `isCurrent`도 보는 사람 기준으로
  고정이다 — 둘 다 행을 흔들지 않는다.
- **`isConnected`로는 정렬하지 않는다.** 그것으로 줄을 세우면 다른 기기가 앱을 켜고 끌
  때마다 행이 솟구쳤다 가라앉는다. 연결 상태는 **배지로만** 말한다.
- **현재 세션이 위인 이유**: 목록의 목적이 "모르는 세션을 찾아 끊기"라, 기준점("이게 나")이
  먼저 읽혀야 나머지를 그것과 대조할 수 있다. 현재 세션만 해제 버튼이 없어서 가운데 있으면
  오른쪽 버튼 기둥이 중간에 끊기기도 한다.
- **최신순인 이유**: 낯선 로그인은 대개 방금 생긴 것이라, 의심스러운 항목이 맨 위로 온다.
- 정렬은 **서버 한 곳**에서 한다(`auth.controller.ts`) — `isCurrent`를 아는 유일한 자리이고,
  거기서 정하면 웹·iOS·Android가 자동으로 같아진다(클라는 받은 순서를 그대로 그린다).

#### 결정됨: 로그인 한 번에 조회도 **한 번**이다

처음에는 소켓이 붙을 때도 목록을 다시 가져왔다. 화면 마운트에서 한 번, 소켓이 붙어서
한 번 — 로그인마다 두 번이었다. **그 두 번째가 가져오는 새 정보가 없다:**

- 다른 기기의 `isConnected`는 **각자의 소켓이 쓴 값**이라 내가 붙는 것과 무관하게 이미 정확하다.
- 내 행은 `isCurrent`가 먼저 걸려 **`isConnected`를 읽지도 않는다**(§4의 배지 규칙).

내가 붙어서 실제로 바뀌는 것은 `socketReady` 하나뿐이고, 그것은 **같은 데이터를 두 갈래로
그리다가 세 갈래로 그리게** 하는 렌더링 규칙의 변화다 — 다시 받아올 이유가 아니다.

→ 서버는 접속 알림에서 **그 연결 자신을 뺀다.** 단 코얼레싱 창 안에서 **혼자 원인일 때만**
그렇다 — 탭 둘이 함께 붙으면 각자를 빼는 순간 서로의 접속을 아무도 모르게 되므로, 그때는
아무도 빼지 않는다. 클라이언트는 **재연결의 `ready`에서만** 가져온다(끊겨 있던 동안에는
알림이 닿지 못해 다른 기기의 변화를 놓쳤을 수 있다).

- **받아들이는 틈:** 마운트 조회와 소켓 `ready` 사이(~100ms)에 다른 기기가 붙거나 끊기면
  놓친다. 막으려면 마운트 조회를 소켓이 자리 잡을 때까지 미뤄야 하는데, 그러면 **소켓
  서비스가 첫 페인트의 인질**이 된다 — 아래의 "소켓은 순수한 덤" 원칙과 정면으로 부딪힌다.
  100ms짜리 경합을 막자고 영구적인 추가 요청을 지불하지 않는다. 다음 이벤트나 당겨서
  새로고침이 메운다.

#### 결정됨: 소켓이 답이 없으면 **두 갈래로 후퇴한다**

소켓 서비스가 죽거나 nginx `/socket`이 잘못되면 presence가 통째로 비어, 서버는 모든
세션을 "연결 없음"으로 내려준다. 그것을 그대로 그리면 멀쩡한 기기들이 전부 `Inactive`로
보인다 — 화면이 **없는 정보를 지어내는** 셈이고, 오류 하나 뜨지 않아 사용자는 그것이
거짓인 줄도 모른다.

→ **내 소켓이 `ready`일 때만 `isConnected`를 믿는다.** 아니면 이 기능 이전의 두 갈래
(`Current`/`Active`)로 물러난다. "모른다"를 "끊겼다"로 옮기지 않는 쪽이 정직하고,
후퇴한 상태가 정확히 예전 동작이라 새 문구·새 배너도 필요 없다.

- 판단 근거: 내 소켓이 붙어 있다 = 소켓 서비스가 살아 있다 = 같은 Redis를 읽는 auth의
  presence도 믿을 수 있다.

#### 결정됨: 소켓은 **인증 상태를 건드리지 않는다**

소켓이 끊기는 이유는 대부분 인증과 무관하다(회선 · 프록시 · 파드 재시작 · 백그라운드).
그것으로 로그아웃하면 **오프라인이 곧 로그아웃**이 된다. 서버가 확정 거절
(`UNAUTHORIZED`)을 보내와도 마찬가지다 — 소켓이 직접 세션을 끝내면 공지가 중복되거나,
이미 끝난 세션의 오류가 새 세션을 끊는다.

→ 소켓은 판단하지 않고 **목록 재조회 한 번**을 시킨다. 그 요청의 401을 이미 있는 중앙
경로가 표식과 대조해 처리한다. 만료(`SESSION_EXPIRED`)일 때만 **기존 공유 회전**
(`api.refreshSession()` · `refreshForRetry`)을 탄다 — 리프레시 자격증명은 1회용이라
소켓이 자기 회전을 시작하면 두 번 소비되어 멀쩡한 세션이 죽는다.

- 소켓의 수명은 **세션 세대**에 묶는다. Android는 `SessionScope` 안의 ViewModel이
  소유한다 — `ServiceContainer`에 두면 앱과 함께 살아 세션 N의 소켓이 세션 N+1까지 남는다.

    여는 **네비 드로어**(사이드바 슬라이드인 + 스크림)로 대체. 같은 nav 마크업을 재사용하고,
    Esc·스크림·닫기 버튼으로 닫으며 열림 시 포커스 이동·배경 스크롤 잠금(Figma `Dashboard /
    Mobile / Drawer (open)` 시안).
- **활성 세션 관리**
  - 세션 목록 조회 (`GET /auth/sessions`)
  - 개별 세션 원격 폐기 (Revoke)
  - 전체 세션 폐기 (Sign out all)
  - 현재 세션 로그아웃 (상단 바 Log out)

### 의도적 제외 (현재 슬라이스에서 빼는 것)

로그인 직후 대시보드 초안에는 인사말·통계 카드·계정 상세·프라이버시 카드가 있었으나
**모두 제거**하고 활성 세션 하나로 좁혔다.

- **통계/차트** — auth 슬라이스에는 집계할 도메인 데이터가 없다(허수 지표는 감점).
- **계정 상세/프로필 편집** — 개인정보 미저장 원칙상 편집·저장할 PII가 없다.
- **프라이버시 안내 카드** — 로그인 화면 문구로 이미 커버된다.

> 필요해지면 후속 슬라이스에서 다시 붙인다. v1은 "세션 관리"라는 **하나의 완결된
> 기능**으로 둔다.

## 3. 사용자 흐름

### 3.1 Happy Path

1. 로그인 성공 → Dashboard 진입
2. 세션 목록 로드 (`GET /auth/sessions`) — 현재 세션은 `isCurrent`로 표시
3. 다른 기기 세션의 `Revoke` 클릭 → 해당 행 폐기 → 목록에서 제거
4. `Sign out all` → 내 모든 세션 폐기 → 로그인 화면으로
5. 상단 바 `Log out` → **현재 세션만** 폐기 → 로그인 화면으로

### 3.2 상태 (Empty / Loading / Error)

| 상태    | 처리                                                                            |
| ------- | ------------------------------------------------------------------------------- |
| Loading | 세션 테이블 자리에 스켈레톤 행(3개) — 셸(사이드바·상단 바)은 먼저 그린다         |
| Empty   | 현재 세션 1개뿐 → "이 기기에서만 로그인돼 있어요" 안내(빈 표 대신 한 줄 문구)     |
| Error   | 테이블 영역에 `Molecule/Alert` Variant=Error + `다시 시도` (셸은 유지)           |

> 현재 세션은 항상 최소 1개 존재하므로 "0건" 진짜 빈 상태는 없다. Empty는 "나 혼자"다.

## 4. 화면 (Figma)

[Dashboard 페이지](https://www.figma.com/design/sTDo6HDslOcRmWL78klk1I/Prism?node-id=2480-60)
— `Dashboard / Desktop / Default`, `Dashboard / Mobile / Default` 2개 시안.

- **테마는 시안을 나누지 않는다.** 색이 전부 Colors 변수(Light/Dark 모드)에 바인딩돼
  있어, 프레임의 적용 모드만 바꾸면 다크가 나온다(웹은 `<html data-theme>`). 별도
  "Dark" 시안을 두지 않는다 — 관리 포인트만 늘고 값은 토큰이 쥔다.
- **콘텐츠는 Active sessions 카드 하나.** 데스크톱은 테이블, 모바일은 스택 카드.

각 행(row)의 구성:

- **Device** — 기기 종류 라벨 + 아이콘, 부제에 짧은 세션 id (§5).
  열 이름이 `Session`이 아니라 `Device`인 이유: 셀에서 먼저 읽히는 굵은 글자가 기기이고,
  카드 제목이 이미 "Active sessions"라 `Session`은 그것을 되풀이할 뿐이다.
- **부제에 "현재/로그인된 세션"을 적지 않는다.** 바로 옆 배지가 이미 그 말을 한다 —
  함께 적으면 같은 말이 두 번 나오고, 좁은 폭에서 줄바꿈까지 만든다(영어·일본어에서
  실제로 그랬다). 대신 **해제 버튼의 접근성 이름**에 넣는다: 목록에 "해제"가 여럿이라
  버튼 글자만으로는 무엇을 끊는지 알 수 없다(§6이 요구하던 라벨이다).
- **좁은 폭에서 "모두 로그아웃"은 목록 *아래*, 카드 푸터에 둔다.** 무엇이 끊기는지 다 본
  뒤에 전체에 대한 행동을 하게 되는 순서다. 마지막 행의 구분선이 그대로 경계가 된다.
  데스크톱은 카드 머리에 그대로 둔다 — 표가 한눈에 들어와 "다 본 뒤"가 이미 성립한다.
  - **폭을 채운다.** 행마다 오른쪽에 "해제"가 세로로 줄지어 있어서, 푸터 버튼까지
    오른쪽에 두면 그 기둥에 이어 붙어 "행 하나 더"로 읽히고 오탭 표적도 겹친다.
  - 이 자리로 내리면서 **확인 단계를 넣었다**(아래). 되돌릴 수 없는 동작이 "해제" 바로
    아래로 오기 때문이다.
- **Started** — 세션 시작 시각 (`startedAt`)
- **Expires** — 만료 시각 (`expiresAt`)
- **Status** — `Current`(Success) / `Active`(Info) / `Inactive`(Neutral) 배지.
  `Active`는 **지금 소켓이 붙어 있다**는 뜻이다(세션의 유효성이 아니다). 내 소켓이
  붙어 있지 않으면 앞의 두 갈래로 후퇴한다(위 결정).
- **(action)** — `Revoke` (현재 세션 행은 미노출)

### 결정됨: 카드의 구획은 **전폭** 구분선으로 나뉜다

세션 카드는 머리 · 세션 행들 · 푸터로 나뉘고, 그 사이마다 1px 선이 **카드 폭을 가로지른다.**
선이 양 끝에서 들여쓰이면 구획이 아니라 "목록 안의 장식"으로 읽힌다.

- 선은 각 구획의 **위**에 둔다. 그러면 규칙이 저절로 성립한다: 행이 몇 개든 첫 행 위
  (= 머리 아래)에 한 줄이 생기고, 마지막 행 아래에는 생기지 않는다 — 거기는 카드 끝이거나
  자기 선을 가진 푸터다.
- 선이 카드 폭을 가로지르려면 좌우 여백을 **카드가 아니라 각 구획이** 가져야 한다
  (웹 `.sessions { padding: 0 }`, 앱 `PrismCard(padding: 0)`). 카드가 여백을 쥐면 선도
  그만큼 안으로 들어온다.
- 여백은 **좌우 24 · 행 위아래 14 · 머리 위아래 20**이다. 시안이 20/18/14로, 앱이 40으로
  제각각이던 것을 웹 값으로 모았다.

### 결정됨: 앱은 당겨서 새로고침을 갖는다

세션 목록은 **이 앱 밖에서도 바뀐다** — 다른 기기에서 로그인하거나 만료되면 화면과 서버가
어긋난다. 화면을 열 때 한 번 묻는 것만으로는 그 어긋남을 사용자가 되돌릴 방법이 없다.

→ **당겨서 새로고침**(iOS `.refreshable` · Android `PullToRefreshBox`). 자동 폴링은 두지
않는다 — 화면에 떠 있는 내내 서버를 두드릴 이유가 없고, 사용자가 궁금할 때 당기는 것으로
충분하다.

- 갱신은 `refresh()`(비우지 않음)를 탄다. 인디케이터가 이미 "받았다"를 말하고 있어,
  목록까지 비우면 화면만 흔들린다.
- 실패해도 인디케이터는 **반드시** 멈춘다. 돌기만 하면 사용자가 할 수 있는 일이 없다 —
  오류는 카드 안에 남는다.
- 웹에는 두지 않는다. 브라우저가 이미 같은 제스처를 페이지 새로고침에 쓰고 있어, 직접
  구현하면 그것과 다툰다.
- iOS는 카드 하나뿐이라 내용이 화면보다 짧다 — `.scrollBounceBehavior(.always)`가 없으면
  당길 여지가 없어 제스처 자체가 일어나지 않는다.

### 결정됨: 진행 중 표시는 **글자를 바꾸지 않는다**

`해제`처럼 목록 안에 있는 버튼은 글자만큼만 자리를 차지한다. 눌렀을 때 "해제" →
"해제하는 중…"으로 바꾸면 폭이 두 배가 되어 행이 통째로 밀린다 — 요청이 짧아 그 흔들림만
깜빡임으로 남는다(실기기에서 그렇게 보였다).

→ **글자는 그대로 두고, 그 행을 흐리게 한다**(`.btn:disabled`와 같은 투명도). 바쁜 것은
버튼이 아니라 **그 세션**이고, 곧 사라질 행이라 예고로도 읽힌다. 크기가 변하지 않아
목록이 흔들리지 않는다. 스크린 리더에는 웹의 `aria-busy`가 같은 말을 한다.

- 스피너는 두지 않는다. 한 바퀴 돌기도 전에 끝나는 동작이라 표시가 아니라 잡음이 된다.
- **갱신은 목록을 비우지 않는다.** 해제 뒤 `load()`(비우고 다시 불러오기)를 부르면 카드가
  "불러오는 중"으로 접혔다가 펴져, 사라질 행 하나 때문에 목록 전체가 깜빡인다. 그래서
  `refresh()`(비우지 않고 갱신)를 따로 둔다 — 비우는 것은 **처음 그릴 때와 재시도**뿐이다.
- **`해제`의 생김새는 플랫폼이 아니라 입력 방식이 가른다.** 포인터(데스크톱 웹)에서는
  판 없는 **Ghost** — 표가 가벼워지고, "눌리는 것"이라는 신호는 hover가 준다. 터치(앱과
  좁은 폭의 웹)에서는 **채운 판(Secondary)** — 손가락에는 hover가 없어, 그 신호가 사라지면
  남는 것은 그냥 글자뿐이다. 웹은 `@media (max-width: 720px)`에서 판을 깐다.
  (터치 표적을 44·48까지 키우는 것과 같은 종류의 갈라짐이다 — 화면이 아니라 손가락 때문이다)

### 결정됨: 전체 로그아웃은 확인을 거친다

`모두 로그아웃`은 **되돌릴 수 없다** — 다른 기기의 세션이 전부 끊기고 지금 이 세션도
끝난다. 그런데 이 버튼이 목록 아래로 내려오면서 행마다 있는 `해제` 바로 밑에 앉게 됐다.
손가락이 조금만 흘러도 하나만 끊으려다 전부 끊긴다.

→ **확인 창을 세운다.** 무엇이 끊기는지 문장으로 적고(`sign_out_all_confirm_body`),
**취소를 왼쪽에 낮은 무게로** 둔다. 웹은 초점도 취소에서 시작한다 — 실수로 Enter를 눌렀을
때 벌어지는 일이 "아무 일도 없음"이어야 한다.

- 창은 **직접 그린다**(웹 `ConfirmDialog` · iOS `PrismConfirmDialog` · Android
  `PrismConfirmDialog`). 시스템 `confirm()`·`.alert`·`AlertDialog`의 기본 껍데기는
  플랫폼 소유라 셋을 나란히 놓으면 여기서만 튄다 — 선택 메뉴를 직접 그리는 것과 같은
  이유다. 창을 띄우는 일(뒤로 가기·바깥 탭·초점)만 플랫폼에 맡긴다.
- `해제`(개별 세션)에는 확인을 두지 않는다. 끊기는 것이 하나이고 어느 것인지 버튼 옆에
  적혀 있으며, 다시 로그인하면 복구된다 — 확인을 남발하면 정작 필요한 곳에서 무시된다.

### 결정됨: 드로어가 환경 설정·로그아웃을 함께 갖는다

좁은 폭에서 상단 바는 **워드마크 · 아바타 · 햄버거**뿐이다(시안). 그러면 데스크톱 상단 바에
있던 테마·언어·사용자·로그아웃이 갈 곳을 잃는다 — 한 줄에 그대로 밀어 넣으면 글자가 한
글자씩 세로로 쪼개지고 가로 스크롤이 생긴다(실제로 그렇게 배포됐다가 고쳤다).

→ **드로어 바닥에 둔다.** 내비게이션 아래 구분선을 긋고 테마 · 언어 · 로그아웃을 쌓는다.
셋 다 이미 있는 컴포넌트를 그대로 쓴다(`Molecule/ThemeSelector` · `Molecule/LanguageSelector` ·
`Atom/Button` Variant=Outline).

- **사이드바와 드로어는 같은 컴포넌트다**(`Organism/Sidebar`). 데스크톱은 이 컨트롤을 상단
  바에 두므로, 불리언 속성 **`Preferences`** 로 가른다 — 기본 `false`(데스크톱), 모바일
  드로어 인스턴스만 `true`. 컴포넌트를 둘로 쪼개면 내비게이션 항목이 늘 때마다 두 곳을
  고쳐야 하고, 언젠가 한쪽만 고쳐진다.
- 푸터는 내비게이션이 남는 공간을 채워(`layoutGrow`) 패널 **바닥**에 붙는다.
- **드로어 안의 선택 메뉴는 트리거 오른쪽으로 편다**(셰브런도 `∨`가 아니라 `>`). 상단
  바에서는 아래가 자연스럽지만, 드로어에서는 스위처가 패널 바닥에 붙어 있어 아래로 열
  자리가 없다 — 그대로 두면 메뉴가 위로 뒤집혀 로그아웃 버튼을 덮는다. 셰브런을 함께
  돌리는 것이 핵심이다: 화살표가 가리키는 곳과 실제로 열리는 곳이 어긋나면, 방향을
  맞춘 의미가 없다. 상단 바(로그인 화면)는 그대로 아래로 연다.
- **축마다 규칙이 다르다.** 펴는 축은 자리가 없으면 반대쪽으로 **뒤집고**(아래로 열던 것은
  위로), 트리거에 걸어 두는 축은 뒤집지 않고 **화면 안으로 당긴다**. 걸어 두는 축을
  뒤집으면 메뉴가 트리거에서 떨어져 어느 트리거가 연 것인지 알 수 없게 된다 — Compose의
  기본 `DropdownMenu`가 옆으로 열 때 실제로 그랬고(세로 여백이 9px 모자랐다), 그래서
  Android는 배치를 직접 정한다(`PreferenceMenuPosition`). 웹은 `min()` 클램프, iOS는
  `.popover`가 같은 일을 한다.

> 시안이 구현을 따라온 경우다. 처음 그린 드로어에는 내비게이션만 있었는데, 구현하면서
> "그럼 로그아웃은 어디로 가는가"가 드러났다. 화면의 원천은 Figma지만, 원천이 답을 갖고
> 있지 않다는 것이 드러나면 **Figma를 고친다** — 코드에만 두면 다음 사람이 시안을 보고
> 같은 구멍에 다시 빠진다.

| 확인 창         | `Molecule/ConfirmDialog` (Outline=취소 · Secondary=확인)      |
| 카드/행/아이콘  | 토큰: `Card` · `Border` · `Soft Blue` · `elevation/sm`, 아이콘 stroke=`Text Strong` |

> **다크 대비 보정(적용 완료)** — 다크 `Primary`를 `#5F92D8`로 밝혀 어두운 배경에서도
> 보이게 했고, 제목·기기명·아이콘은 `Navy`(다크 배경용) 대신 **`Text Strong`**
> 토큰(Light `#162338` / Dark `#FFFFFF`)에 바인딩해 다크에서 묻히지 않게 했다.

## 5. 데이터 / API 컨트랙트

세션 API는 auth 서비스에 이미 존재한다([auth.controller.ts](../apps/server/services/auth/src/auth.controller.ts)).
api 서비스가 아니라 auth 서비스가 발급/폐기의 원천이다([auth.md §6.2](./auth.md)).

### `GET /auth/sessions`

**Response 200**: `SessionListItem[]` — 순서는 서버가 정한다(현재 세션 → `startedAt` 최신순, §4).

```ts
interface SessionInfo {
  id: string;
  startedAt: string; // ISO
  expiresAt: string; // ISO
}
interface SessionListItem extends SessionInfo {
  isCurrent: boolean; // 서버가 요청의 sessionId와 대조해 계산
  isConnected: boolean; // socket 서비스가 쓴 presence를 auth가 읽어 계산
}
```

### `POST /auth/sessions/:id/revoke`

소유자 범위 확인 후 해당 세션 폐기(`revokeOwnedSession`). 남의 세션 id를 넣어도
자기 것이 아니면 폐기되지 않는다(폐기 DoS 방지, [auth.md §6.2](./auth.md)).
**Response**: 성공 시 폐기, 대상 없음/미소유 시 실패 응답.

### `POST /auth/sessions/revoke-all`

내 **모든** 세션 폐기(`revokeAllSessions`) → 화면은 로그인으로.

### `POST /auth/logout`

**현재 세션만** 폐기(`revokeSession(sessionId)`) → **Response 204**.

> **정적 경로 우선** — 컨트롤러 선언 순서상 `sessions/revoke-all`을
> `sessions/:id/revoke`보다 **먼저** 둔다. 아니면 `revoke-all`이 `:id`에 흡수된다.
> `/auth/sessions`도 `/auth/:provider`보다 뒤에 두면 provider로 먹힌다.

### 결정됨: 기기 **종류만** — 기기명·브라우저·위치는 담지 않는다

Figma 시안은 `MacBook Pro · Chrome · Seoul, KR`을 보여준다. 그대로 담으려면 UA 원문과
IP를 저장해야 하는데, 그러면 개인정보 미저장 원칙이 깨진다. 그렇다고 아무것도 주지
않으면 "이 세션이 내 폰인지 회사 PC인지"를 알 수 없어, 목록의 본래 목적(모르는 세션을
찾아 끊기)이 흐려진다.

→ **가운데를 택한다.** 계약에 `device` 하나만 더한다 — 값은 정해진 목록이다:
`iphone · ipad · galaxy · pixel · android · mac · windows · desktop · unknown`.

알아볼 수 있는 만큼은 **브랜드까지** 좁히고(포트폴리오 화면에서 "휴대폰"보다 "iPhone"이
훨씬 잘 읽힌다), 모르면 한 단계 넓은 값으로 둔다.

- **원문은 저장하지 않는다.** 로그인 요청의 User-Agent를 그 자리에서 네 갈래로 접고
  버린다(`services/auth/src/session/device.ts`). 저장소에 남는 것은 enum 하나뿐이라,
  저장소가 통째로 유출돼도 브라우저·OS 버전·기기 모델이 새어 나가지 않는다.
- **IP는 읽지도 않는다.** 위치는 이 슬라이스에서 다루지 않는다 — 국가만 담아도 geo-IP
  의존이 생기고, 로그인 화면의 "개인정보를 저장하지 않습니다"와 부딪힌다.
- **모르면 좁히지 않는다.** UA가 없거나 알아볼 수 없으면 `unknown`이다. 라벨이 조금 덜
  친절한 것이, 없는 정보를 지어내는 것보다 낫다. 두 경우가 실제로 자주 온다:
  - Chrome의 **UA 축약**은 안드로이드 모델을 `K`로 지운다(접근 로그에서 확인) →
    브랜드를 지어내지 않고 `android`로 접는다.
  - **iPadOS Safari는 기본이 데스크톱급**이라 스스로를 `Macintosh`로 소개한다 →
    `mac`으로 접힌다. 앱은 자기가 무엇인지 알기에 `Prism (iPad)`를 보내 정확히 잡힌다.
- **브랜드 로고는 쓰지 않는다.** 아이콘은 폰·태블릿·모니터 세 실루엣뿐이다 — 상표를 앱에
  심는 일이고, 목록에서 필요한 것은 형태 구분뿐이다.
- **앱도 같은 규칙으로 읽힌다.** iOS·Android가 브라우저와 같은 토큰(`iPhone`/`iPad`/
  `Android`+`Mobile`)이 든 User-Agent를 보내, 서버는 분류 규칙 하나만 갖는다.
- **예전 세션은 목록에서 사라지지 않는다.** 이 필드가 생기기 전에 만들어진 세션은
  값이 없다 — 거부하지 않고 `unknown`으로 접는다.

> **시안도 같은 것을 그린다.** 처음에는 `MacBook Pro · Chrome · Seoul, KR`이었지만,
> 계약에 없는 값을 시안이 계속 보여주면 다음 사람이 그것을 구현하려 든다 — 제목 줄은
> 기기 종류(`Mac`·`iPhone`·`Windows`), 부제는 짧은 세션 id(`#a3f1c204`)로 맞췄다.

## 6. 접근성 / i18n

- 테마(라이트/다크/시스템) · 언어 스위처는 로그인 화면과 동일 컴포넌트 재사용
- 다크 대비: 위 §4 보정으로 텍스트/아이콘/버튼 모두 대비 확보
- `Revoke`/`Sign out all`은 파괴적 액션 — 키보드 포커스 가시성 + 스크린리더 라벨
  필요 — **구현됨**: `해제: Mac · 로그인된 세션 · #8430e7a7` 형태로, 기기 종류(§5)와
  현재 여부를 담는다(웹 `aria-label` · Android `contentDescription` · iOS
  `accessibilityLabel`).
- **영역 이름은 내비게이션 항목에만 붙인다.** 웹은 `<nav aria-label>`이 그 둘만 감싸므로
  자연스럽지만, SwiftUI에서 컨테이너에 `.accessibilityLabel`을 걸면 그 이름이 **자식
  전부를 덮는다** — 실제로 드로어 전체에 걸었더니 테마·언어·로그아웃이 모두
  "내비게이션"으로 읽혔다. `.accessibilityElement(children: .contain)`을 함께 써야
  영역 이름과 자식 이름이 공존한다.
